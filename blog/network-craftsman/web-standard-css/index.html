CSS : comment le navigateur transforme une structure HTML en interface
#

Une page Web peut contenir des titres, des paragraphes, des liens et des images sans pour autant ressembler à un site professionnel.

Les éléments sont présents, le contenu est accessible et le navigateur sait comment interpréter le document. Pourtant, la page peut paraître désorganisée : les éléments s’enchaînent verticalement, les espaces sont peu maîtrisés et rien ne permet véritablement de distinguer les différentes parties de l’interface.

Comment passe-t-on de ce document à une page structurée visuellement, avec des colonnes, des couleurs, des espacements et une disposition adaptée aux écrans ?

La réponse se trouve principalement dans CSS, le langage utilisé pour décrire la présentation des documents Web.

Dans le précédent article, nous avons découvert les fondations du Web et le rôle de HTML. Nous allons maintenant examiner comment CSS permet de contrôler l’apparence et la disposition des éléments d’une page.

L’objectif n’est pas de mémoriser une liste de propriétés. Il est de comprendre le fonctionnement du langage afin de pouvoir prendre des décisions de conception éclairées.

1. HTML et CSS : deux responsabilités différentes
#

HTML et CSS interviennent dans la construction d’une page Web, mais ils ne répondent pas à la même question.

HTML décrit la structure et la signification du contenu. CSS définit les règles de présentation qui déterminent notamment son apparence et sa disposition.

Prenons cet exemple :

<h1>Bienvenue sur mon site</h1>
<p>Je présente ici mes services numériques.</p>
<a href="/services/">Découvrir mes services</a>

Ce document contient un titre, un paragraphe et un lien. Le navigateur sait interpréter ces éléments et les afficher.

Mais si nous souhaitons un titre plus grand, une couleur particulière, un espace entre les éléments et un bouton visuellement identifiable, nous devons définir des règles de présentation.

C’est le rôle de CSS.

Nous pouvons représenter cette complémentarité de la manière suivante :

  • HTML : quels contenus composent la page et comment sont-ils structurés ?
  • CSS : comment ces contenus doivent-ils être présentés et disposés ?
  • JavaScript : quels comportements et quelles interactions faut-il implémenter ?

Cette distinction est conceptuelle. Les trois technologies peuvent interagir, et HTML comme CSS possèdent déjà certaines capacités liées au comportement ou à l’interaction. Toutefois, cette répartition constitue un excellent point de départ pour comprendre l’architecture d’une interface Web.

2. Une règle CSS : une instruction de présentation
#

CSS repose sur un système de règles.

Une règle permet de sélectionner un ou plusieurs éléments du document, puis de leur appliquer des déclarations.

Observons cet exemple :

h1 {
  color: #2563eb;
  font-size: 2.5rem;
}

Cette règle contient trois parties :

  • h1 est le sélecteur : il cible les éléments correspondant au nom de balise h1.
  • color et font-size sont des propriétés CSS.
  • #2563eb et 2.5rem sont les valeurs attribuées à ces propriétés.

Le navigateur interprète ces déclarations et calcule la présentation des éléments concernés.

La propriété color définit ici la couleur du texte. La propriété font-size définit sa taille.

Une règle CSS ne dessine donc pas directement une image de la page. Elle décrit des contraintes et des valeurs à partir desquelles le navigateur calcule le rendu.

Cette différence est importante : CSS est un langage déclaratif. Nous décrivons le résultat de présentation recherché plutôt que de programmer manuellement chaque étape du dessin.

3. Comment associer CSS à HTML ?
#

Il existe plusieurs manières d’intégrer des règles CSS à un document HTML.

La feuille de style externe
#

C’est généralement la méthode à privilégier pour un site Web organisé.

Dans le document HTML :

<head>
  <meta charset="utf-8" />
  <title>Mon site</title>
  <link rel="stylesheet" href="/css/style.css" />
</head>

Dans le fichier style.css :

body {
  font-family: system-ui, sans-serif;
  color: #222;
  background-color: #f5f5f5;
}

L’élément HTML link permet de référencer la feuille de style externe.

Cette séparation présente plusieurs avantages : les règles sont regroupées dans un fichier dédié, plusieurs pages peuvent réutiliser les mêmes styles et la présentation devient plus facile à maintenir.

La feuille de style interne
#

Il est également possible d’écrire des règles CSS dans un élément style, généralement placé dans le head du document.

<style>
  body {
    font-family: system-ui, sans-serif;
  }
</style>

Cette méthode peut convenir à des exemples autonomes ou à certains besoins spécifiques, mais elle est moins pratique lorsque plusieurs pages partagent la même présentation.

Les styles en ligne
#

Enfin, un attribut style permet d’appliquer directement des déclarations à un élément.

<p style="color: red;">Un texte en rouge.</p>

Cette technique existe, mais son utilisation systématique rend les styles plus difficiles à centraliser et à faire évoluer.

Pour apprendre et construire des projets maintenables, il est préférable de comprendre les feuilles de style externes et de les utiliser comme approche par défaut.

4. Les sélecteurs : comment cibler les bons éléments ?
#

Avant de modifier l’apparence d’une page, CSS doit déterminer quels éléments sont concernés par chaque règle.

C’est le rôle des sélecteurs.

Sélectionner par type d’élément
# 

p {
  line-height: 1.7;
}

Cette règle cible tous les paragraphes correspondants dans le document.

Sélectionner par classe
#

HTML permet d’attribuer une classe à un élément :

<p class="introduction">Nous concevons des solutions numériques.</p>

CSS peut ensuite cibler cette classe :

.introduction {
  font-size: 1.2rem;
  color: #444;
}

Une classe peut être utilisée sur plusieurs éléments. Elle est particulièrement utile lorsque nous voulons appliquer un même traitement à différents contenus.

Sélectionner par identifiant
#

Un identifiant peut également servir de cible :

<section id="services">
  <h2>Nos services</h2>
</section>

#services {
  padding: 3rem 1.5rem;
}

La différence principale est que la classe représente une catégorie d’éléments, tandis qu’un identifiant doit désigner un élément unique dans le document.

En pratique, les classes constituent un outil central pour organiser les styles d’une interface.

Il existe de nombreux autres sélecteurs : sélecteurs d’attributs, combinateurs, pseudo-classes et pseudo-éléments. Il n’est pas nécessaire de tous les maîtriser immédiatement. Il faut d’abord comprendre comment une règle identifie les éléments auxquels elle s’applique.

5. La cascade : pourquoi un style peut-il en remplacer un autre ?
#

Imaginons que nous écrivions deux règles différentes pour les paragraphes :

p {
  color: black;
}

p {
  color: blue;
}

Quelle couleur le navigateur doit-il appliquer ?

Dans cet exemple simple, les deux règles ont la même origine, la même importance et la même spécificité. La seconde déclaration l’emporte parce qu’elle intervient plus tard dans l’ordre de la cascade.

Mais la réalité peut être plus complexe.

Une feuille de style peut contenir plusieurs règles qui ciblent un même élément. Certaines proviennent de nos fichiers CSS, d’autres de feuilles de style importées ou de règles du navigateur. Des déclarations peuvent également être influencées par l’héritage, la spécificité et l’utilisation de !important.

La cascade détermine comment ces déclarations sont départagées.

La spécificité permet notamment de comparer la force relative des sélecteurs lorsque les autres critères pertinents sont équivalents.

Par exemple :

p {
  color: black;
}

.introduction {
  color: green;
}

#presentation {
  color: blue;
}

Si un paragraphe possède simultanément la classe introduction et l’identifiant presentation, la règle ciblant l’identifiant est normalement prioritaire entre ces trois règles, toutes choses égales par ailleurs.

Il ne faut donc pas considérer CSS comme une simple liste d’instructions exécutées de haut en bas. Le navigateur doit résoudre l’ensemble des règles applicables pour déterminer les valeurs finales.

Cette compréhension devient particulièrement utile lorsqu’un élément ne présente pas l’apparence attendue.

Dans ce cas, les outils de développement du navigateur permettent d’inspecter les règles appliquées, les déclarations remplacées et les valeurs calculées.

6. Le modèle de boîte : comprendre les dimensions d’un élément
#

Chaque élément HTML participe à la mise en page selon des règles de disposition. Pour les éléments auxquels le modèle de boîte CSS s’applique, il est utile de distinguer plusieurs zones.

Le modèle de boîte classique comprend :

  1. Le contenu : le texte, l’image ou les autres éléments contenus.
  2. Le padding : l’espace intérieur entre le contenu et la bordure.
  3. La bordure : la limite qui entoure le padding et le contenu.
  4. La marge : l’espace extérieur autour de la boîte.

Considérons cet exemple :

.card {
  width: 300px;
  padding: 20px;
  border: 2px solid #ccc;
  margin: 16px;
}

Avec le modèle content-box, la largeur déclarée de 300px concerne le contenu seul. Il faut ensuite ajouter le padding et les bordures pour calculer la largeur extérieure de la boîte.

La largeur totale devient donc :

300 + 20 × 2 + 2 × 2 = 344px

Les marges ajoutent ensuite de l’espace autour de cette boîte.

Ce comportement peut surprendre lorsqu’on commence à organiser une interface.

Pour rendre le calcul des dimensions plus intuitif, de nombreux projets utilisent :

*,
*::before,
*::after {
  box-sizing: border-box;
}

Avec border-box, la largeur déclarée inclut le contenu, le padding et les bordures. Dans notre exemple, la largeur extérieure de la boîte reste ainsi de 300px, hors marges.

Le modèle de boîte est fondamental pour comprendre les espacements, les dimensions et les alignements d’une interface.

7. La mise en page : organiser les éléments dans l’espace
#

CSS ne se limite pas à changer la couleur d’un texte ou à arrondir les angles d’un bouton. Il permet également de définir comment les éléments se positionnent les uns par rapport aux autres.

Deux mécanismes sont particulièrement importants : Flexbox et Grid.

Flexbox : organiser les éléments sur un axe
#

Flexbox convient notamment aux dispositions en ligne ou en colonne.

Par exemple, pour aligner un logo à gauche et une navigation à droite :

<header class="site-header">
  <a class="logo" href="/">Mon entreprise</a>

  <nav aria-label="Navigation principale">
    <a href="/services/">Services</a>
    <a href="/contact/">Contact</a>
  </nav>
</header>

.site-header {
  display: flex;
  justify-content: space-between;
  align-items: center;
  gap: 2rem;
}

La déclaration display: flex crée un contexte de mise en page Flexbox.

justify-content contrôle la répartition des éléments sur l’axe principal, tandis que align-items contrôle leur alignement sur l’axe transversal.

Flexbox est particulièrement adapté aux navigations, aux groupes de boutons et aux alignements de composants.

Grid : organiser les éléments en lignes et colonnes
#

CSS Grid permet de construire des dispositions bidimensionnelles.

Imaginons une liste de services :

<section class="services">
  <article class="service">Service 1</article>
  <article class="service">Service 2</article>
  <article class="service">Service 3</article>
</section>

.services {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 1.5rem;
}

Le navigateur répartit les trois éléments sur trois colonnes de largeur comparable.

La propriété gap définit l’espace entre les éléments de la grille.

Flexbox et Grid ne sont pas concurrents : ils répondent à des besoins différents et peuvent être combinés dans une même interface.

Il faut retenir une idée essentielle : nous n’avons pas besoin de placer manuellement chaque élément à une coordonnée précise. Nous pouvons décrire une organisation, puis laisser le moteur de mise en page calculer la position des éléments.

8. Concevoir pour plusieurs écrans
#

Une interface Web ne sera pas nécessairement consultée sur un ordinateur. Elle peut être affichée sur un téléphone, une tablette, un ordinateur portable ou un écran large.

Une disposition confortable sur un grand écran peut devenir inutilisable sur un écran étroit.

CSS permet de créer des règles conditionnelles grâce aux media queries.

Par exemple :

.services {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr));
  gap: 1.5rem;
}

@media (max-width: 700px) {
  .services {
    grid-template-columns: 1fr;
  }
}

Sur les écrans dont la largeur du viewport est inférieure ou égale à 700px, la grille passe à une seule colonne.

Cette valeur est un choix de conception, pas une norme universelle. Le bon point de rupture dépend du contenu et de la disposition que nous cherchons à préserver.

Une conception responsive ne consiste pas simplement à créer une version pour ordinateur et une autre pour téléphone. Elle consiste à adapter la présentation aux contraintes de l’espace disponible.

Les unités relatives, les tailles fluides, Flexbox, Grid et les media queries permettent de construire des interfaces qui s’adaptent à ces contraintes.

9. Ce que le navigateur fait avec CSS
#

Lorsque le navigateur reçoit un document HTML et ses feuilles de style, il doit combiner les informations pour produire une représentation visuelle.

De manière simplifiée, il :

  1. analyse le HTML et construit le DOM ;
  2. analyse les feuilles de style et détermine les règles applicables ;
  3. calcule les styles des éléments ;
  4. effectue les calculs nécessaires à la mise en page ;
  5. peint les éléments et produit le rendu à l’écran.

Cette représentation simplifie un processus plus complexe : les navigateurs peuvent effectuer certaines étapes différemment, réutiliser des calculs ou les répéter lorsque le document ou son environnement change.

Par exemple, lorsqu’une fenêtre est redimensionnée, les règles de mise en page peuvent devoir être recalculées. Lorsqu’une classe est modifiée en JavaScript, le navigateur peut devoir recalculer les styles et actualiser le rendu.

Le CSS ne produit donc pas une image figée. Il définit des règles que le navigateur utilise pour calculer une présentation en fonction du document, de la fenêtre, des polices, des ressources disponibles et d’autres facteurs.

C’est cette capacité qui permet à une même page de s’afficher différemment selon le contexte, sans que nous ayons besoin de créer une image distincte pour chaque taille d’écran.

10. Exercice : construire une première mise en page
#

Pour mettre ces notions en pratique, créons une petite page de présentation de services.

Commencez par créer deux fichiers : index.html et style.css.

Dans le document HTML, ajoutez :

  • un en-tête contenant le nom du site et une navigation ;
  • une section d’introduction avec un titre, un paragraphe et un lien ;
  • une section présentant trois services ;
  • un pied de page.

Associez ensuite la feuille de style externe au document.

Votre objectif est de :

  1. définir une typographie et des couleurs cohérentes ;
  2. limiter la largeur du contenu principal ;
  3. utiliser Flexbox pour la navigation ;
  4. utiliser Grid pour les trois services ;
  5. ajouter des espacements à l’aide du padding, de la marge et de gap ;
  6. adapter la grille aux écrans étroits.

Ne cherchez pas à obtenir un résultat spectaculaire dès la première tentative. Commencez par une structure lisible et une disposition fonctionnelle.

Lorsque le résultat ne correspond pas à vos attentes, inspectez les éléments avec les outils de développement du navigateur. Vérifiez les styles calculés, les dimensions des boîtes et les règles qui contrôlent la mise en page.

L’objectif de cet exercice est de comprendre les mécanismes qui produisent le rendu, plutôt que de reproduire aveuglément une solution trouvée ailleurs.

Conclusion
#

CSS est bien davantage qu’un ensemble de propriétés décoratives. C’est un langage qui permet de décrire l’apparence, les dimensions et l’organisation spatiale des éléments d’un document Web.

Les sélecteurs déterminent les éléments ciblés. La cascade permet de résoudre les règles concurrentes. Le modèle de boîte explique les dimensions et les espacements. Flexbox et Grid permettent d’organiser les éléments, tandis que les media queries contribuent à adapter la présentation aux différents écrans.

Maîtriser ces mécanismes change la manière d’aborder le développement Web : au lieu d’accumuler des corrections visuelles, on apprend à comprendre pourquoi le navigateur produit un résultat donné.

Dans le prochain article, nous passerons de ces mécanismes techniques à une question de conception : comment décomposer une page en blocs, esquisser son interface avec Excalidraw et choisir les éléments HTML sémantiques qui correspondent à chaque partie ?

L’objectif sera de relier la réflexion sur l’interface à la structure du document et à sa future présentation.
